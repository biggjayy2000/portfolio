Why they belong together

Most junior portfolios show one side. These two share a lab and a point of view: the scanner finds the exposed .git directory and the permissive CORS policy, and the triage tool detects the requests that follow when someone finds them. Building both meant thinking like the attacker and the analyst on the same afternoon.

probe the app→ find the weakness→ detect the traffic→ write the report

How they were built

Verified, not just written

114 tests across the two projects, including end-to-end runs: one scans a deliberately misconfigured server over a real socket, the other triages a 74-event incident and checks every rule fires.

The negative cases matter

Every detection has a test proving it stays quiet on normal traffic. A rule that fires on everything is not detection; it is noise with a severity label.

Zero dependencies

Standard library only, in both. Nothing to install, so they run on any machine with Python — including a locked-down work laptop.

Limits stated up front

Passive scanning only, one URL per run; detection is threshold-based with no geolocation or baselining. Both READMEs say so rather than implying more capability than exists.
